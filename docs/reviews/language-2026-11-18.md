# Language review, 2026-11-18

Scope: `app/i18n/ro.ts` and `app/i18n/en.ts` (1,036 lines each), read in full; screenshots in `.qa/copy-ro/` spot-checked (retro notes and Kanban board screens). Spec section 7 and the tour copy were used as the rulebook. No source file was changed.

Severity: **Wrong** (error or misleading) / **Unnatural** / **Inconsistent** / **Polish**. Keys are given as `key`.

---

## Romanian

### Wrong

**R1. Role names after "ca / Doar / {role} ..." lack the definite article.** The screenshot of the retro screen shows "Se așteaptă ca facilitator să continue." A common noun needs "facilitatorul"; "Gazdă" would be as bad.
- Keys: `phase.waiting`, `phase.waitingFor`, `goal.waitingConfirm`, `commit.waitingStart`, `limits.waiting`, `replenish.waitingStart`, `summary.onlyFacilitator` ("Doar facilitator poate publica"), `goal.hint` ("{role} îl confirmă"), `poker.facilitatorOnly`.
- Fix: give the role a second, definite form (`role.facilitator.kanban.def`: "facilitatorul"; Scrum: "Scrum Master-ul"; host: "gazda") and use it in these keys. Keep the indefinite form for `phase.youAre` ("Ești facilitator") and `lobby.facilitatorIs` ("primul facilitator").

**R2. Incident puzzle: level words do not agree with the indicator.** `Indicators` pairs are errors low/high, memory free/full, queue empty/full, latency normal/high, disk free/full, traffic usual/double. The Romanian level words have one fixed gender: "erori: scăzut", "memorie: plin", "coadă: plin", "latență: ridicat" are wrong (should be scăzute / plină / plină / ridicată). `token.level.empty` ("goală") and `normală` are feminine, the rest masculine, so it is accidentally right for some and wrong for others.
- Keys: `token.level.low|high|free|full`, `puzzle.incident.condition` ("{indicator}: {level}"), `held.incident`.
- Fix: needs a code change, so the level key becomes per indicator (`token.level.errors.low` = "scăzute", `token.level.memory.full` = "plină" ...), or reword to an invariant form such as "nivel scăzut / nivel ridicat" and drop "plin/liber/goală" for "nivel maxim / nivel minim". Also use a sentence form: `puzzle.incident.condition`: "{indicator} {level}" ("coada plină") instead of the colon, so that "Dacă erori: scăzut și coadă: plin" becomes "Dacă erorile sunt scăzute și coada este plină" (needs definite forms of the indicator as well: "erorile", "memoria", "coada", "latența", "discul", "traficul").

**R3. Typo in imperative.** `tour.note.do`: "apoi adaug-o." -> "apoi adaugă-o."

**R4. Garbled sentence.** `phase.scrum.work.practice`: "Scrum Guide cere echipei să-și scrie propria definiție, dacă organizația nu are un standard, a calității pe care trebuie să o aibă un Increment" is not grammatical in this order. Proposed: "Scrum Guide spune că, dacă organizația nu are un standard, echipa își scrie propria Definition of Done, adică ce calitate trebuie să aibă un Increment. Trecerea de la un element la altul costă timp aici: este regula proprie a jocului."

**R5. "Verificare" names two different things.** It is the peer review (`item.review` "Verifică", "verificator", "În verificare") and the title of the Sprint Review / Delivery review screen (`inspect.title`: "Verificare"; `step.scrum.inspect.increment`: "Verifică Increment"; `phase.scrum.inspect.role.developers`: "verifică Increment și rezultatul"). A beginner reading "ia o verificare" and "Verificare" will mix them up. Use "inspect" vocabulary for the event: `inspect.title` -> "Inspectare" (or "Sprint Review" / "Delivery review" depending on the framework), `step.scrum.inspect.increment` -> "Inspectează Increment-ul", `phase.scrum.inspect.role.developers` -> "Developers inspectează Increment-ul și rezultatul", `phase.scrum.inspect.purpose` -> "Sprint Review-ul inspectează rezultatul Sprint-ului ...".

**R6. Bad gender for a mixed audience.** Participles that force masculine for a player: `lobby.status.ready` "Pregătit" (-> "Gata"), `start.tour.facts` "singur" (-> "fără echipă"), `puzzle.role.solo` "Lucrezi singur la acest element" (-> "Lucrezi doar tu la acest element"), `tour.idea.text` / `.kanban` "de unul singur" (-> "doar tu, cu colegi simulați").

### Unnatural

**R7. Technical terms: article convention is inconsistent.** The same file has "Sprint-ul", "timebox-ul", "backlog-ului", "cache-ul", "LGTM-ul", "Review-urile" (articulated) and, in the same screens, bare English terms used as Romanian subjects or objects: "Sprint Planning începe", "Sprint Review verifică", "Daily Scrum verifică", "Product Owner este o persoană", "Scrum Master dezvăluie", "Sprint Goal atins", "arată Increment", "Velocity este", "Throughput a crescut", "Cycle time s-a scurtat", "Sprint continuă după Daily Scrum". Bare nouns as sentence subjects read like headlines or a translation.
- Rule proposed: a singular English term used as subject or object takes the hyphenated Romanian article ("Sprint Review-ul verifică", "Daily Scrum-ul", "Product Owner-ul", "Scrum Master-ul", "Sprint Goal-ul", "Increment-ul", "Product Backlog-ul", "Sprint Backlog-ul", "velocity-ul", "throughput-ul", "cycle time-ul", "work item age-ul" is too clumsy: rephrase as "vechimea elementelor (work item age)"). Plurals take the Romanian ending after a hyphen ("Sprint Goal-uri", "WIP limit-uri") or stay bare in headings and buttons. "Developers" stays bare (plural, used as a collective: "Developers lucrează").
- Keys (all that contain such a sentence): `phase.scrum.plan.purpose`, `.role.productOwner`, `.role.scrumMaster`; `phase.scrum.work.purpose`, `.role.scrumMaster`, `.role.productOwner`; `phase.scrum.daily.purpose`, `.role.*`; `phase.scrum.inspect.purpose`, `.role.productOwner` ("arată Increment-ul"), `.role.scrumMaster`; `phase.scrum.retro.purpose`, `.role.*`; `phase.resume.scrum`; `script.scrum.*` ("cele două Sprint Goal" -> "cele două Sprint Goal-uri"); `step.scrum.plan.commit` ("pentru Sprint Backlog-ul"); `inspect.goalMet|goalMissed`; `observation.*` (Throughput, Cycle time, Sprint Goal); `tour.wrong.text` ("Sprint Review ți-l arată" -> "Sprint Review-ul ți-l arată"); `tour.daily.text`; `daily.*`.

**R8. "un apel al tău / un apel propriu" is a calque of "your own call".** `start.how`, `privacy.p6`, `tour.end.text`. Use "pe un apel separat" / "pe un apel între voi". `start.how` proposed: "Între 3 și 6 jucători, fiecare pe dispozitivul lui. Vorbiți pe un apel separat sau în aceeași încăpere: jocul nu transmite sunet."

**R9. "lucrător" (worker) for a person on a software team.** `item.label.workers` "Lucrători", `item.pairSlot` "Are nevoie de un al doilea lucrător", `item.joinSecond`, `item.noteWaitingPair`, `phase.waiting*`, `work.next.waitingPartner|join|held`, `retro.help.*`, `observation.work.waitingForPair`, `daily.summary.pair`, `held.order|incident`, `agreement.*`. "Lucrător" is factory vocabulary. The same state also has three names: "partener" (`item.status.waiting`), "pereche", "al doilea lucrător". Proposed: one name, "încă o persoană" / "partener" in all keys: `item.pairSlot` "Are nevoie de încă o persoană", `item.joinSecond` "Alătură-te ca partener", `item.label.workers` "Cine lucrează", `item.status.waiting` "Așteaptă un partener" (keep), `daily.summary.pair` "# elemente așteaptă un partener". (The same problem exists in English, see E6.)

**R10. "control al muncii în desfășurare / control al WIP".** `start.framework.kanban.line` ("fără control al muncii în desfășurare"), `limits.none` ("Runda 1 nu are intenționat control al WIP"), `board.noLimits`. "Control al" needs "controlul/control asupra" and "intenționat" is misplaced. Proposed: `start.framework.kanban.line` "Un flux continuu de cereri: runda 1 fără limite pentru munca în desfășurare, runda 2 cu limite." `limits.none` "Runda 1 nu are limite, intenționat: așa se vede ce face munca necontrolată. Kanban cere echipei să o controleze."

### Inconsistent

**R14. ### Wrong

### Inconsistent

**E5. Same state, different names.**
- "pair" / "partner" / "second worker": `item.status.waiting` "Waiting for a pair", `item.pairSlot` "Needs a second worker", `work.next.waitingPartner` "waits for a second worker", `item.joinSecond`. Pick "second person" or "partner" everywhere.
- "flow measures" (`tour.review.text.kanban`, `summary.learned.kanban`) vs "flow metrics" elsewhere.
- Button vs hint: `item.promiseHelp` "I will help" and `item.withdrawHelp` "Withdraw my help", while `tour.held.do`, `daily.replan` and `work.next.help` say "promise help". Rename the buttons "Promise help" / "Withdraw help" (Romanian: "Promite ajutor" / "Retrage ajutorul"). The same fix applies in Romanian (`item.promiseHelp` "Voi ajuta" is future tense, not the imperative the spec requires for buttons).
- `item.status.rejected` "Escaped defect" vs `inspect.verdict.rejected` "Wrong answer (escaped defect)".
- `start.frameworkLegend`/`summary.framework` "Framework" (Romanian "Metodă"): Kanban is not a framework in the Kanban Guide's wording; use "Method" in English too.
- `retro.help.p.try.*` and `bot.note.try.*` are imperatives ("Take a review within ...", "Finish an item before ...", "Join an item ...") but sit under "We will try" and the Romanian is first person plural ("Luăm o verificare", "Terminăm"). Make English first person plural: "We take a review within {limitSec}.", "We finish an item before we start another." Keys: `retro.help.p.try.review|pair|info|wip|estimates|review_care|focus|limits|finish_first`, `bot.note.try.1|2`.

Biggest gains: R1 (definite role forms), R2 (indicator-specific levels), R7 (one article rule for English terms), R5 and R9 (vocabulary), R14/R15/R16/R17 (one term per thing).

**English: 8/10.** Clear and correct apart from a handful of slips. Biggest gains: E1 ("error rate"), E2 ("guided tour"), E3 (quote the labels), E5 (one name for pair/partner/second worker, button "Promise help", proposals in first person plural), E7 (cut the long paragraphs), B2 (expand LGTM, define timebox and WIP).
